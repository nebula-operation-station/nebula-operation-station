# One-step enrollment plan (ADR 0013)

Status: **in progress, 2026-11-12.** [ADR 0013](../adr/0013-one-step-enrollment.md)
is Accepted (2026-11-11, previously Proposed) with the maintainer's decisions
on Q1–Q9. Merged on `main`: EN-01 to EN-08, EN-10 (without NetBird) and EN-13,
and EN-09 as a package that is not yet mounted (see the status table below).
Open: EN-12, EN-14 and EN-15 part 2 (the NetBird parts), now reshaped by
the ADR amendment of 2026-11-12 (no NetBird Management API; EN-11 dropped;
see "NetBird without Management API (2026-11-12)" below). (previously:
"Open: EN-11, EN-12, EN-14 and EN-15 part 2"; before that "plan, not
started, 2026-11-11 … only EN-01 is done".) Decisions that shape the tickets: a 25-character
pairing code (24 Crockford data characters = 120 bits, plus a mod-37 check
character, `XXXXX-XXXXX-XXXXX-XXXXX-XXXXC`; Q1), 15 minutes total offer
lifetime by default (Q2), groups `nos`/`nos-managed` (Q3; the NetBird
service user and the policy reads are superseded by Q8), inventory host
creatable in the dialog (Q4), one mismatch ends the offer (Q7), no NetBird
Management API: the operator supplies a one-off setup key, NOS never
creates, revokes or attributes keys or peers (Q8, decided 2026-11-12),
NetBird by hand for hosts that cannot reach NOS (Q9). (previously: "NetBird
service user in the executor vault, … policies only read and warned on
(Q3), … peer attribution checked against the real NetBird API with the
time-window fallback otherwise (Q8)".)

This plan turns ADR 0013 into PR-sized tickets: one agent job each, tests
first, `make check` per Go ticket, no new dependencies.

## NetBird without Management API (2026-11-12)

Maintainer decision of 2026-11-12 on ADR 0013 Q8 / EN-11: NOS does not talk
to the NetBird Management API. The operator creates a one-off setup key in
the NetBird dashboard and enters it in the one-step dialog or with the
executor-local CLI; the script (or a later SSH step) passes it to the
NetBird client by `0600` key file or environment, never in argv; the join
is checked on the host with `netbird status`; NOS cannot revoke the key and
tells the operator to do it. The rules are in
[ADR 0013, "Amendment 2026-11-12: no NetBird Management API"](../adr/0013-one-step-enrollment.md#amendment-2026-11-12-no-netbird-management-api).
EN-16a (this change) is documentation only; no code was changed.
