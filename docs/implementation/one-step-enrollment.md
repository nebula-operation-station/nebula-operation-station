# One-step enrollment plan (ADR 0013)

Status: **plan, not started, 2026-11-11.** ADR 0013 is Proposed; only EN-01
is done. Tickets EN-02 onwards start after the maintainer has decided the open
questions Q1–Q9 of [ADR 0013](../adr/0013-one-step-enrollment.md). EN-03 and
EN-04 are pure libraries and may start before acceptance if the maintainer
agrees, because they change no behaviour.

This plan turns ADR 0013 into PR-sized tickets: one agent job each, tests
first, `make check` per Go ticket, no new dependencies.

## Rules every ticket keeps

| # | Rule | ADR |
| --- | --- | --- |
| E1 | No pin without a matching salted pairing code **and** a HIGH approval with user verification; commit re-probes and pins only the approved key | D3, D4 |
| E2 | The executor decides the code match and builds the permit; the server only forwards operator input | D4 |
| E3 | Offer ID ≥ 128 bits from `crypto/rand`, stored only as SHA-256, logged only as an 8-hex prefix; single use; 15-minute expiry; revocable; uniform `404` for every refusal; forwarded headers honoured only from configured trusted proxies, addresses normalised first, a trusted proxy's request without a usable header refused without charging any rate-limit bucket; the same client address in every audit record of the flow | D2, D7 |
| E4 | `from=` addresses and the NetBird management URL come from executor-local configuration only | D5, D6 |
| E5 | The NetBird token and setup keys stay in the executor vault and exist at rest only encrypted there; scripts are rendered on demand, never stored, cached or logged; typed NetBird calls only, no generic proxy; setup keys one use, ≤ 1 h, auto-group only the managed group; created only after a NetBird offer permit approved with the security key; revoked unconditionally when the offer is final, the key ID kept, `netbird_setup_key_revoke_failed` audited and the revoke retried until it succeeds or the key expired | D1, D2, D6 |
| E6 | The script is downloaded over the NOS TLS origin, hash-checked, then run; never `curl \| sh`, never `-k`; command and script use `umask 077`, `mktemp -d` and a `trap`, so no setup key is readable by others or left behind after a failure; no other path carries the setup key: "Show script" renders a placeholder instead, and the browser download is refused for NetBird offers | D1, D5, D7, D8 |
| E7 | Script-printed addresses are untrusted hints; endpoints are validated like inventory endpoints | D5 |
| E8 | CLI enrollment, `known_hosts` import, bulk **Enroll hosts** and the ADR 0008 guest join stay byte- and behaviour-compatible | D9 |
| E9 | Named constants for every limit: offer lifetime, open offers (10), offers per hour (30), probes per offer (5), rejected codes (3), open NetBird offers (2), setup keys per hour (5), script size (64 KiB), download rate (10/min, 60/h per client address, IPv6 per /64), forwarded header (1 KiB, 16 entries), NetBird join wait (60 s) | D2, D5, D7 |
| E10 | No secret (setup key, token, offer ID, salt) in logs, errors, results, fixtures or commit messages | AGENTS.md |

## Dependencies

No new Go modules. NetBird is called with `net/http` and `encoding/json`;
SHA-256 and randomness come from `crypto/sha256` and `crypto/rand`. On hosts
the script needs a POSIX `sh` with 64-bit arithmetic, coreutils (`sha256sum`,
`base64`, `cut`, `tr`, `mktemp`), `curl` or
`wget`, and for the NetBird option the official NetBird package repository.

## Order

EN-01 → EN-02 → (EN-03, EN-04, EN-05, EN-06, EN-11 in parallel) → EN-07 →
EN-08 → (EN-09, EN-13) → EN-10 → EN-12 → EN-14 → EN-15. Without NetBird
(Q3 "manual step"), EN-11 and EN-12 are dropped and the rest stays valid.
