# Milestone 0: implementation status

Milestone 0 (security prototype) is implemented and its acceptance criteria are covered by tests in `test/security/`. This page records what exists, where it deviates from or sharpens the specification, and what must be done before later milestones rely on it.

## What exists

| Spec requirement | Implementation | Tests |
| --- | --- | --- |
| UID separation, executor files private | `internal/fsguard`; executor refuses to start on a non-0700 data dir, refuses to run as root | `TestM0Privileged_ServerUserCannotReadExecutorFiles` |
| Socket with `SO_PEERCRED` method sets | `internal/peercred` (transport credentials + interceptors), table in `internal/executor/roles.go` | `TestM0_UnknownUIDIsRejected`, `TestM0Privileged_UnknownUIDIsRejectedAcrossProcesses`, role tests |
| Canonical request, RFC 8785 | `internal/canonical` using `github.com/gowebpki/jcs` | golden bytes + independently computed digest, mutation tests |
| Permit digest, binding, single use per host | `internal/permit` | `TestM0_SubstitutionAfterApprovalIsRejected`, permit unit tests |
| Executor-side artifact hashing | `permit.Authorize` hashes artifact and parameters itself | substitution tests |
| Executor-side WebAuthn verification | `internal/webauthnverify` using `github.com/go-webauthn/webauthn/protocol` | `TestM0_ReplayedAssertionIsRejected`, verifier unit tests |
| CLI unlock into in-process keyring | `internal/keyring`, `cmd/nebula unlock` | keyring tests, `TestM0_WrongPassphraseDoesNotUnlock` |
| Executor state survives restarts in the strict direction (H02) | `internal/executordb` (`executor.db`, SQLite, 0600) | `TestH02_*`, `TestH02Privileged_ExecutorDBIsPrivateToTheExecutor`, executordb unit tests |

## Decisions taken during implementation

These sharpen the spec without changing its architecture. Each is a candidate for an ADR if contested.

1. **`request_version: 1`** is part of the canonical request, so a future change of the canonical form cannot collide with old digests.
2. **Set semantics in the canonical form.** `credential_refs` and `resolved_targets` are sorted before encoding. Order carries no meaning (stage assignment is bound through `stage_plan_hash`).
3. **Execution IDs are single-use.** Re-proposing an execution ID with different content is rejected (`execution_id_reused`). Identical re-proposal returns the live permit; once the permit is gone (expired, discarded, revoked by Lock) the ID is spent and a new execution must be created.
4. **Browser approval needs an active privileged session** for every risk class, not only LOW. The CLI path does not need one; the admin UID on the executor host is the authentication.
5. **Lock revokes all permits**, not only the privileged session. Locking means stop.
6. **The server role may call `Lock`.** Locking only removes capability, so the web UI's "Lock executor" works without a CLI.
7. **Three failed approvals discard a pending permit.**
8. **CLI-only permits expose no browser challenge.**
9. **Root is never an admin.** Admin users are personal accounts and must be members of the socket group `nebula-rpc`.
10. **Unlock is all-or-nothing with one passphrase.** Unencrypted, group-readable, symlinked or weak (RSA < 3072) key files are refused.
11. **One parameters hash, one meaning.** Parameters are sent with the proposal, must hash to `parameters_hash`, and the executor keeps the RFC 8785 form. Duplicate keys are rejected, and numbers must already be canonical and exactly representable (`1.0`, `1e0`, `-0`, `9007199254740993` are rejected). `nebula approve` shows the full canonical parameters with control and bidi characters escaped.
12. **Unknown UIDs are dropped during the handshake**, before any request is read; the per-method table then applies to known UIDs. Clients (`nebula`, `nebula-server`) verify that the socket is served by the executor's UID before sending anything.
13. **Keys:** only OpenSSH-format private keys (bcrypt KDF) are accepted; a Lock issued while an Unlock is decrypting wins.
14. **Lint toolchain:** staticcheck 2026.2.1 cannot read Go 1.27 export data yet, so `make lint` runs it under Go 1.26.9. The module requires Go 1.26.
15. **`executor.db` stores only what makes the executor stricter** (H02): spent execution IDs and WebAuthn signature counters. Permits, approvals and the privileged session are never written to disk, so every restart starts locked, with no permits and no session. A crash or restart is a revocation. This narrows spec 03 and 05, which list permits and session state among the contents of `executor.db`.
16. **Durable before visible.** An execution ID is bound in `executor.db` before `Propose` returns a permit, and a new signature counter is stored before `Verify` reports success. If the store fails, the call fails closed with `storage_error`; the detail goes to the audit log only, and a counter that cannot be stored does not count as a failed approval.
17. **Counters never go down.** The stored counter only rises (`ON CONFLICT … WHERE excluded.sign_count > sign_count`); at startup each credential starts at the higher of the credential file and the store, so neither a stale credentials file nor a lost row can lower it.
18. **One executor per data directory.** `executordb.Open` holds a non-blocking `flock` on the data directory for the life of the process, so a second executor on the same directory refuses to start, independent of SQLite's connection handling. SQLite runs on one connection with `locking_mode=EXCLUSIVE` (set before WAL, so there is no `-shm` file), WAL and `synchronous=FULL`. The data directory must be an absolute path. The file is created `0600` with `O_EXCL|O_NOFOLLOW` and checked with `fsguard`, as is the `-wal` file; a looser or foreign-owned file is refused, never repaired. Migrations are embedded, forward-only, one transaction each; a database from a newer version is refused.
19. **Retention:** spent execution IDs are pruned at startup 30 days after their request expired. The cutoff never passes the newest stored `bound_at`, so a clock that jumps forward at boot cannot prune live IDs. Expired requests are rejected by `canonical.Canonicalize`, so a pruned ID can only return inside a new request with a new expiry, and that needs a fresh approval like any new execution.

## Known gaps (must close before the named milestone)

| Gap | Risk | Close by |
| --- | --- | --- |
| The executor accepts the risk class proposed by the server. A compromised server could label a dangerous action LOW and get it auto-approved inside an active session. | High | **Before Milestone 4** (first real execution): executor recomputes effective risk from the signed or locally trusted manifest, scanner result and host criticality, and takes the maximum. |
| `nebula approve` shows the artifact hash, not the script. A compromised server could propose an expected action whose artifact differs from what the operator assumes. | Medium | Milestone 7: executor-side artifact store; approval shows the script (or its signed manifest identity) |
| Milestone 4 must send `Permit.Parameters` (canonical bytes held by the executor) to the host, never the raw bytes of a run request. | High if missed | Milestone 4 |
| The protected-path checks are tripwires: the hook can be bypassed, the label and the agent identity are self-declared, and a `pull_request` workflow runs the PR's own workflow file. The binding control is branch protection with required code-owner review and dismissal of stale approvals. | Medium | Configure on GitHub before the first agent PR |
| A missing `executor.db` is recreated empty (counters and spent IDs restart; the executor logs a warning when credentials exist). Refusing would break upgrades from before H02. Because of the exclusive lock, a backup cannot read the database while the executor runs. | Low | Milestone with `nebula backup` (spec 15): back up through the executor, restore `executor.db` with its `-wal`, and refuse a missing database once an install marker exists |
| No WebAuthn registration ceremony; credentials are read from `webauthn-credentials.json`. | Medium | Milestone 2 |
| No vault for non-SSH secrets. | Low until modules need secrets | Milestone 2 |
| `peercred.Listen` changes the process umask briefly; call it only during startup. | Low | documented |
| Executor events are not yet signed; audit goes to the structured log. | Medium | Milestone 10 |

## How to run the tests

```
make test              # unit and acceptance tests, race detector
sudo -E make test-privileged   # multi-UID tests (need root to drop privileges)
make lint              # vet, staticcheck (Go 1.26.9), buf lint
make fuzz              # short fuzz runs of host-input parsers
```
