# Help assistant plan (ADR 0014)

Status: **plan, not started, 2026-11-11.** Waiting for the maintainer's
answers to the open questions of
[ADR 0014](../adr/0014-help-assistant.md) (Proposed). Release placement
(Q11, recommended): after hb01 (docs embedded and served under `/help`) and
va09 (LLM settings model).

This plan turns ADR 0014 into PR-sized tickets. It follows the maintainer
request of 2026-11-11: ask in the UI how to do something (for example set
up the connection to `192.168.22.1`) and get the exact steps and commands
from the connected LLM, beside the static FAQ (hb00).

## Rules every ticket keeps

| # | Rule | ADR |
| --- | --- | --- |
| A1 | Advisory only: no execution, no proposal, plan, permit, lease, schedule or approval, no prefilled form; no endpoint takes assistant output as input; import-boundary allowlist for the assistant packages | D1, D4 |
| A2 | Knowledge only from the embedded handbook, FAQ and admin guide of the running release, chunked by H2 (split at H3 and paragraphs above `MaxChunkBytes`); no web access, no runtime additions | D2 |
| A3 | Every answer cites chunk IDs that were in its prompt; links are built by NOS from its index, never from model output | D2, D4 |
| A4 | Inventory facts only per-question opt-in, only for hosts the question names and the user can see, from a fixed struct (name, endpoints, criticality, enrollment state, OS family, NOS source addresses); never secrets, vault, keys, fingerprints, audit, logs, findings or flows; delimited as untrusted data | D3 |
| A5 | Output is a strictly validated JSON object, rendered as escaped text; commands checked by the deterministic validator (command catalog, cited-docs shape, deny patterns, value origin); flags shown, commands never rewritten; label "generated by an LLM – check before running" on every answer | D4 |
| A6 | LLM settings like va09: admin-only URL, model, credential reference, fresh WebAuthn assertion per change, audited; own `assistant.enabled` switch, default off | D5 |
| A7 | Server egress only to the configured LLM URL through a dedicated dialer (lab-only rule of ADR 0011 A1.4 by default, no redirects, no proxy variables, verified TLS or explicit plain `http` without credential) | D5 |
| A8 | Per-user and global rate limits, size and token limits, timeouts, bounded worker pool; limits are named constants | D5 |
| A9 | No question or answer text in logs or audit; conversations not stored by default; opt-in storage bounded and per user | D5 |
| A10 | No new dependencies; tests first; `make check` per Go ticket; no network in tests except loopback | AGENTS.md |

## Tickets

Order is the suggested merge order; tickets with the same number may run in
parallel. **Protected** means a path in `.github/protected-paths.txt` and a
maintainer review. Package names are suggestions; one package, one
responsibility.

### Phase B: deterministic parts (no LLM; after AS-02, may start after AS-01 behind the off switch)

| ID | Order | Scope | Paths | Protected | Acceptance |
| --- | --- | --- | --- | --- | --- |
| AS-03 | 3 | Docs chunk index over the embedded handbook, FAQ and admin guide (uses hb01's embedding; *verify* its package) | `internal/helpdocs/` (new) | no | One chunk per H2 with the `/help` anchor and heading path; H3 split above `MaxChunkBytes` (6 KiB), paragraph parts `#pN` above that; test fails on a missing or duplicate anchor; code blocks extracted per chunk; index deterministic (same input → same IDs); only the three corpus sources, no runtime additions |
| AS-04 | 3 | Lexical retrieval (BM25), German/English normalisation, reviewed synonym table | `internal/helpsearch/` (new) | no | Golden queries: "enroll 192.168.22.1" and "ich will auf IP 192.168.22.1 die Connection einrichten" rank the handbook enrollment section and admin guide 7.1/7.2 in the top 3; commands and flags (`enroll-script`, `--from`) match as whole tokens; top `k` = 6 and `MaxContextDocBytes` 24 KiB respected; deterministic tie order; fuzz on query input, no panics |
| AS-05 | 3 | Command catalog and validator | `internal/helpcmd/` (new); reads the `nebula` command tree only if `cmd/nebula` exposes it without changes (*verify*; otherwise built from the docs' code blocks) | no; yes (`cmd/nebula/`) only if the command tree must be exported there | Unknown `nebula` subcommand or flag (also after `sudo`) → red flag naming it; shape not in a cited chunk's code blocks → amber; deny patterns (`\| sh`, `\| bash`, `curl`/`wget` with non-placeholder URL, `rm -rf`, `chmod 777`, `dd`, `eval`, backticks, `$(…)`, undocumented `;`/`&&` chains, writes to `/etc/` not in the docs) → red; address or host argument not from the question or facts → amber; control, bidi and zero-width characters rejected; validator never rewrites; **docs cross-check test**: every `nebula …` command in the corpus code blocks exists in the catalog (doc drift fails the build) |
| AS-06 | 3 | Fact projector | `internal/helpfacts/` (new) | no | Fixed struct only (name, ID, ≤ 4 endpoints, criticality with source label, enrollment state enum, OS family/release, NOS source addresses per Q6); hosts selected only from address/CIDR/name/ID literals in the question, ≤ `MaxFactHosts` 10 and `MaxFactBytes` 4 KiB; "not in inventory" for unmatched addresses; user authorisation identical to the inventory page (a host the user cannot see never appears); hostile names (instructions, control characters, overlong, invalid UTF-8) rejected or escaped; import-boundary test: no import of vault, keyring, credentials, audit, execution logs, vuln store, traffic store |

## Protected paths touched by this plan

`docs/adr/` (AS-01); `docs/spec/` and `docs/threat-model.md` (AS-02);
`test/security/` and `test/browser/` (AS-12); `cmd/nebula/` only if AS-05
needs the command tree exported; `internal/web/auth/` only if AS-08 cannot
reuse the existing fresh-assertion helper unchanged.

## Dependencies outside this plan

- **hb01**: docs embedded in the binary and served under `/help` with
  stable anchors (AS-03, AS-10).
- **va09**: LLM settings model (AS-08) and possibly a shared LLM client
  (AS-07).
